# ポケット四皇モンスター

## What This Is

鴨川周平（にーくら）の友人グループ「四皇」をテーマにした、**収集 → 育成 → 編成 → AI自動戦闘** の
モンスターゲーム。HTML/JS 製、個人プロジェクトで配布しない。理想はゲーム版ポケモンではなく
**アニメ版ポケモンの戦い方** ——プレイヤーは技を直接選ばず、采配だけで勝敗を動かす。

ゲーム本体（`docs/開発計画_v6.md` が正典、Phase 0〜14 完了）とは別に、それを作るための
**補助ツール群**（戦闘テスト・技ラボ・音ラボ・四皇モン制作ツール）が `dist/` に4画面ある。
**この GSD マイルストーンが扱うのは、後者の開発基盤だけ。** ゲーム本編には触らない。

## Core Value

**にーくらが作ったもの（四皇モン・技・音）が、容量を気にせず保存でき、実際の戦闘に出てくること。**

今はこの両方が成立していない。保存は 5MB の壁と消失リスクを抱え、制作ツールで作った個体は
戦闘画面から一度も参照されていない。ここが直れば、他は全部おまけ。

### Out of Scope

- **ChromiumOS の導入** — OS を替えても保存制限は1バイトも変わらない。ChromiumOS は Chromium を
  内蔵した OS であって描画エンジンは同一、かつサンドボックスとCrostiniの境界でファイル読み書きは
  **むしろ悪化する**。求めていた「軽い・保存できる・Claudeに都合がいい」の3条件は、
  ローカルサーバー＋`--app` 専用ウィンドウで全部満たせる。払う代償に対して得るものが無い。
- **`dist/` の単体HTML形式をやめること** — 掟「外部ファイル参照はゼロ」。配布用は焼き込みのまま
  維持し、軽い版は開発モードとして**別に**出す。
- **`src/sfx_bank.js` の解体・再生成** — `tools/gen_sfx.py` が要求する CC0パック2種
  （`assets/webgameattacksfxcc0/`, `assets/webgamesfxcc0kenney/`）がこのマシンに存在しない。
  616KB のこのファイルが79音の**唯一の実体**であり、壊すと復元手段がない。触らない。
- **ゲーム本編の Phase 15「コスト経済」以降** — `docs/開発計画_v6.md` が正典。GSD は基盤だけ見る。
- **既存44技の一斉目視確認** — 既定モーションが変わって見た目が変化しても、分岐1箇所と
  技クリエーターの上書きで後からいつでも直せる。前もって全部見る価値がない（にーくら判断）。
- **画像ファイルを増やすこと** — 掟4。エフェクトも背景もコードが描く。

## Context

**現状の計測値（2026-08-17 時点）**

| 項目 | 実測 |
|---|---|
| `dist/` 4ファイル合計 | 2.97 MB |
| `src/sfx_bank.js` | 616 KB（base64 79音）。各 dist HTML の **71〜89%** を占める |
| `assets/` 実体 | 40 KB（スプライトのみ。CC0元素材は不在） |
| localStorage キー | 7個（技ライブラリ・音設定・保存スロット・草むらプール・自動保存・シーン音・鳴き声ディレイ） |

**今日の調査で判明した、設計と実装のズレ**

- `src/battle.tpl.html` は **localStorage を一切読まない**。`mon.shadow` / `mon.cry` /
  `mon.customMoves`、保存スロット、草むらプールは全て戦闘から到達不能。出場するのは
  `ROSTER_A`/`ROSTER_B` のベタ書き個体だけ（`battle.tpl.html:769-796`）。
- `CLAUDE.md:216` は鳴き声を「読み込み時に自動」で圧縮すると書いているが、実装は**手動**。
  `creator.tpl.html:1309` に「勝手に焼き直さん。軽くするかは鴨川が決める」とあり、これは
  掟8（音の決定権は100%鴨川）の徹底による**意図的な設計**。ドキュメントの記述の方が誤り。
- `shioumon_creator_slots` と `shioumon_wild_pool_v1` は設計上そもそも上書きしないため、
  積み上がる一方。鳴き声は最大3MB弱まで素通しで入るので、数体で 5MB 枠に届く。
- `resolve()` が `battle.tpl.html:474` と `creator.tpl.html:464` で**シグネチャ違いで重複**。
  掟4が「必ず同じ判断にする」と要求している当の箇所。
- `src/fx_audio.js` は完全にデッド（どのテンプレートにもトークンが無い）。15KB。
- `audiolab.tpl.html:359` に掟違反の `confirm()` が残存（消す系は二度押しの規約）。
- `verify_audio.js` / `verify_ui.js` は検出したエラーで `process.exit` を呼ばず、**常に exit 0**。
  壊れていても「通った」ように見える。
- 全テンプレートが Google Fonts（DotGothic16）を外部ロードしており、「外部参照ゼロ」と矛盾。
  フォールバック指定があるので機能は落ちない。
- `audiolab.tpl.html` に未使用の `ANIMS` が焼き込まれている。
- `starter_moves.js` の44技は既存6ジェネレータの使い回しのみ。HANDOFF.md にある
  にーくらの日付入り・最優先の不満と一致。

**背景**

にーくらは当初「ChromiumOS を自分用に組んで、軽くて保存できる開発環境を作りたい」と考えていた。
掘った結果、痛みの正体は OS でもブラウザでもなく **「ブラウザのサンドボックスの中にいる」という
立場そのもの**、および 616KB の base64 を毎回パースする起動コストだった。
過去に何度も「HTML形式の方が優れている」と回答されてきたが、その主張は UI レイヤーの話であり、
**シェル（起動・保存・実機連携）レイヤーの不満には一度も答えていなかった**。この2層は独立に選べる。

## Constraints

- **設計の掟**: `docs/開発計画_v6.md` 末尾の禁止事項26個が正典（`CLAUDE.md` §4 に要約）。
  特に効く： 決定論を壊さない／可変dtを戦闘計算に使わない／技ごとのアニメコードを書かない／
  画像ファイルを増やさない／音IDをベタ書きしない／`confirm()` を分かれ道に置かない。
- **`dist/` は単体で開ける**: 外部ファイル参照ゼロを維持する。軽量化は別モードで達成する。
- **`src/sfx_bank.js` は不可触**: 自動生成物だが元素材が無く復元不可。手で編集しない。
- **音の決定権は100%にーくら**: 圧縮も割り当ても自動で決めない（掟8）。
- **戦闘で `Math.random()` を使わない**: 演出の揺らぎも `battleRng` を消費せず種から決める。
- **配布しない**: 個人プロジェクト。認証・課金・マルチユーザーの考慮は一切不要。
- **Windows 11 / Node v26 / Deno 2.9 / Bun 1.3 / Python 3.13** が導入済み。追加インストール不要。

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| ChromiumOS を採用せず、ローカルサーバー＋`--app` 専用ウィンドウで解決する | 保存制限はブラウザ製品名ではなくサンドボックスに由来する。OS 変更では1バイトも改善せず、ファイルI/Oは悪化する | — Pending |
| 保存を localStorage からファイルへ移す。サーバーが無い時は localStorage にフォールバック | 上限が消え、オリジン非依存になり、git で戻せて、Claude が直接読める。単体HTML動作も壊さない | — Pending |
| `dist/` の base64 焼き込みは維持し、軽量版は開発モードとして別に出す | 「外部参照ゼロ」は掟であり意図的な設計。`sfx_bank.js` を触らずに軽さを取る | — Pending |
| 制作ツール→戦闘の配線を、保存層と同じフェーズでやる | 保存のファイル化が配線の前提。分けるとファイル形式を二度決めることになる | — Pending |
| 技分類は「近接／遠距離／遠隔」の3つ。定義は**実体が空間を進むか** | 「雷は迎撃不可」は分類の中に技名が混ざった一般化の失敗。この定義なら新技も一意に決まり、迎撃不可が結論ではなく導出結果になる | — Pending |
| 相殺判定は3分類ではなく2分類（遠距離か否か）で門前払いする | 既存の弾↔弾／光線↔光線／貫通の力関係は全て「遠距離」の内側の話。入れ子を明示すれば `resolveClash` の中身を触らずに済む | — Pending |
| 分類ごとの既定モーション： 近接=踏み込む／遠距離=前へ出す／遠隔=その場で溜める | 棒立ちだと技が本人と無関係に見える。遠隔で腕を振ると「飛ばした」ように見え、実体が飛ばないという分類の意味と絵が食い違う | — Pending |
| 既存44技の一斉目視確認はしない | 後からいつでも直せる（分岐1箇所＋技クリエーターの上書き）。前もって全部見るコストに見合わない | — Pending |
| GSD の管理範囲は開発基盤のみ。ゲーム本編は `docs/開発計画_v6.md` のまま | 正典を2つにしない。移行作業を発生させない | — Pending |
