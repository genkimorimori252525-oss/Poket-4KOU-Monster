**Gathered:** 2026-08-18

<domain>
## Phase Boundary

**アイコン一発で開く専用ウィンドウと、軽い開発用ビルド。**

にーくらが最初の相談で言った「デスクトップに置けて、開くだけで進行中の開発状況が見やすく配置される」を
実際に作るフェーズ。加えて、開発中の画面読み込みを軽くする。

対象は SHELL-01〜05 の5件。**SHELL-05（ダッシュボード）は当初の要件定義で取りこぼしていたものを
このフェーズの discuss で拾い直したもの**（にーくらの一番最初のメッセージに書かれていた）。

**含まない**: 保存層のファイル化（Phase 3）。技分類（Phase 4）。
**含まない**: `dist/` の形式変更。`dist/` は**バイト単位で不変**を保つ（このフェーズ固有の制約。下記参照）。

</domain>

<decisions>
## Implementation Decisions

### 起動とブラウザ（SHELL-01）
- **Chromium を使う。ただし新規インストールはしない。**
  Playwright が検証用に同梱している本物の Chromium が既にこのマシンにある:
  `C:\Users\genki\AppData\Local\ms-playwright\chromium-1234\chrome-win64\chrome.exe`
  Edge とは別プロセス・別プロファイルなので、にーくらが求めていた「Edge の常駐（Copilot・サイドバー・
  拡張）から離れる」は満たせる。新しいソフトを入れる必要がない。
- **`--app` モード＋専用 `--user-data-dir`** で起動する。タブもURLバーも出ない専用ウィンドウになり、
  普段使いの Edge/Chrome のプロファイルとも完全に分離される。
- **起動スクリプトはブラウザのパスをハードコードしない。** Playwright の Chromium → Chrome → Edge の
  順に実在するものを探して使う。Playwright のバージョンが上がるとディレクトリ名（`chromium-1234`）が
  変わるため、固定パスに依存すると次のアップデートで壊れる。次のプロジェクトへ持ち出すときも効く。
- ⚠ **Windows の Chromium に `--version` を叩かない。** GUI を立てようとして返ってこない
  （実際に2分でタイムアウトした）。存在確認はファイルの有無で行う。

### ダッシュボード（SHELL-05）
- アイコンを開くと**ダッシュボードが出る**。制作ツール直行ではない。
- 出すもの: 作った四皇モンの一覧／技の本数／保存容量／検証の最終結果とその古さ／
  4画面（戦闘・技ラボ・音ラボ・制作ツール）への入口。

### ダッシュボードの2つの穴（パターンマッピングで判明・解決済み）

**穴1 —— 「最終更新」を出すデータが存在しない。** `shioumon_creator_slots` に保存時刻のフィールドが
無い。当初の記述はデータがある前提で書かれていた。
→ **Phase 3 へ回す。** ここで `savedAt` を足すと**保存データの形を変える**ことになり、その直後の
SAVE-07（無損失移行）が変えたばかりの形を運ぶことになる。移行の直前に形を触るのは筋が悪い。
Phase 3 で保存がファイルになれば**ファイルの更新時刻がそのまま正確な最終更新になる**——足さずに手に入る。
**Phase 2 のダッシュボードは一覧だけ出し、時刻の列は作らない。**

**穴2 —— 検証結果を読むファイルが存在しない。** `tools/verify_*.js` はどれも合否を書き残さない。
ダッシュボードを開くたびに Playwright を起動する案は却下（1〜2分かかり、ブラウザが立ち上がる）。
→ **検証チェーンに結果を書かせる。** 各段（audio / ui / creator / resolve）の合否と実行時刻を
小さな JSON に残し、サーバーがそれを読んでダッシュボードへ渡す。
- **表示には必ず「古さ」を添える**（例:「4段すべて通過・2時間前」）。3日前に通った記録は
  「通っている」ではない。古さが見えないと、直っていないものを直ったと誤認する——
  このプロジェクトが Phase 1 で殺したばかりの失敗の形そのものだ。
- 結果ファイルは git 追跡しない（実行環境ごとの一時的な事実であって、リポジトリの状態ではない）。
- **Phase 1 で作った非ゼロ終了の挙動は変えない。** 結果を書くのは追加であって置き換えではない。
- **重要な制約 —— 保存データはサーバーからは見えない。** 四皇モンも技も、今は localStorage の中にある。
  サーバー（Bun）はファイルしか読めないので、**この2つはダッシュボードの JS が
  クライアント側で localStorage から読む**。したがって:
  - ダッシュボードが `http://localhost:PORT` で開かれる以上、**見えるのは localhost オリジンに
    保存されたデータだけ**。にーくらが今まで `file://` で開いていたなら、**一覧は空に見える**。
    これは故障ではない（CLAUDE.md 219行の「保存データは開き方ごとに別の箱」そのもの）。
  - **この状態は Phase 3 の移行で解消する。** ダッシュボードに「データが見つからない場合は
    開き方が違う箱を見ている可能性がある」旨を1行出して、故障と誤解されないようにする。
- **見た目に凝りすぎない。** これは配布物ではなく自分用の現在地表示。1画面に収め、
  更新は開いた時に読むだけでよい（自動更新やリアルタイム監視は作らない）。

### サーバー（SHELL-04）
- **Bun を使う。** 導入済み（1.3.13）。起動が速く、単一バイナリなので次のプロジェクトへ
  フォルダごとコピーして使える。`tools/serve.js` の19行の静的配信は活かす。
- **1コマンドで起動する。** `npm run dev` 相当の入口を1本用意する。
- **次のプロジェクトへ持ち出せる形にする。** これは SHELL-04 の本体であり、にーくらの
  「もう二度と次のプロジェクトでもこの悩みはしたくない」への答え。サーバー＋起動スクリプト＋
  ダッシュボードの雛形を、プロジェクト固有の記述から切り離しておく。

### 軽量ビルド（SHELL-02, SHELL-03）
- **`src/sfx_bank.js` は読むだけ。1バイトも書き換えない。** 616KB の base64 が79音の唯一の実体で、
  CC0 元素材はこのマシンに無い。ビルド時に**デコードして `dist-dev/se/` へ書き出す**だけ。
- **`dist/` の4ファイルはバイト単位で不変。** これはこのフェーズ固有の制約
  （Phase 1 では `dist/` の再生成を許可したが、それはテンプレートを変えたから。
  このフェーズはテンプレートを変えないので、`dist/` が動いたらそれはバグ）。
- 軽量版は `dist-dev/` に出す。音は鳴らす分だけ後から読む（起動時に79音を全部デコードしない）。
- `build.js` に開発モードを足す形にする。既存の `node build.js` の挙動は変えない。

### Claude's Discretion
- ダッシュボードの具体的なレイアウトと配色（ドット絵の画面に合う方向で）
- `dist-dev/` の音声ファイル形式（元の data URI の MIME をそのまま使うのが素直）
- 遅延ロードの実装方式（`SoundBank` の既存インターフェースを保つのが前提）
- 起動スクリプトの形式（`.cmd` / `.ps1` / `.lnk` のどれか、あるいは組み合わせ）

</decisions>

## Existing Code Insights

### Reusable Assets
- `tools/serve.js` —— 19行の静的配信サーバー。**土台は既にある**。保存APIは Phase 3 で足す
- `build.js` —— `MODULES`（トークン→ソース）と `TARGETS`（テンプレート→出力）の2表。
  開発モードはここに分岐を足す
- `src/sfx_bank.js` の `SoundBank` —— 音の再生インターフェース。遅延ロード化してもここの外形は保つ
  （`playSys()` / `playMovePhase()` を通す掟8を壊さない）
- `npm run verify` —— Phase 1 で4段になった。`dist/` が動いていないことの確認にも使える

### Established Patterns
- ビルドは単純な文字列置換。`/*__TOKEN__*/` を `src/*.js` の中身で差し替える
- 検証は Playwright を叩く単体の node スクリプト
- コメントと識別子は日本語と英語が混在

### Integration Points
- `build.js` —— 開発モードの分岐
- `tools/serve.js` —— `dist-dev/` も配信できるようにする
- `package.json` —— 起動用の script を足す（Phase 1 で `verify:resolve` を足した先例あり）

### 触ってはいけないもの（全フェーズ共通）
- **`src/sfx_bank.js`** —— 復元不可。読むのは可、書くのは不可
- **`dist/` の4ファイル** —— このフェーズでは**バイト単位で不変**
- **決定論** —— 戦闘で `Math.random()` を使わない、固定タイムステップを崩さない

<specifics>
## Specific Ideas

- にーくらの原文（最初の相談）: 「デスクトップに置けて、開くだけで進行中のゲーム開発状況や
  プロジェクトを画面で見やすく配置してくれるとか」——**ダッシュボードはこの一文が出典**。
- 「重い」の主因は Edge ではなく **864KB の HTML を開くたびに 616KB 分の base64 をデコードしている**こと。
  ブラウザを替えても軽くならない。軽さは `dist-dev/` 側で取る。
- SHELL-03 の「大幅に軽くなる」は、`sfx_bank.js` の 616KB が外に出れば HTML は 1/3 以下になる見込み。
  実測して記録すること（主張ではなく数字で）。

</specifics>
