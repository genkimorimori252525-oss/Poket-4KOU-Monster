# Roadmap: ポケット四皇モンスター（技の作り直し）

## Overview

このマイルストーンが直すのは、**技が仕組みに追いついとらん**という一点。

相殺（Phase 12）・分類（Phase 4）・コスト経済（Phase 15）・反動と間 —— 順に作ってきたが、
**技は44本ぜんぶそれより前のもの**や。だから今の技はどの仕組みも踏まえとらん。
数えたら威力は 6〜52 の狭い帯で、**威力60以上が0本**。大技も無ければ捨て技との差も薄い。
コスト経済の「格上を食う」も、相殺の力関係も、これでは働きようが無い。

にーくらが挙げた参照（Pokémon Pearl の ROM）は使わん —— 市販ゲームの中身を
吸い出すことになるけん。**そもそも要らん。** 足りんのはよその参考やのうて、
**四皇モン自身の仕組みから逆算すること**やけん。

順番には理由がある。**捨てる前に、捨てても壊れんことを確かめる**（Phase 1）。
逆にしたら、何が原因で壊れたか分からんくなる。次に**式を決めてから**技を作る
（Phase 2 → 3）—— 式が無いまま数字を置いたら、次に技を足す人が同じ迷いをする。

`src/sfx_bank.js` は全フェーズを通して不可触。新しい絵は1枚も増やさん（掟4）。
にーくらの保存個体と自作技には**指1本触れん**。

## Phases

**Phase Numbering:**

- Integer phases (1, 2, 3): Planned milestone work
- Decimal phases (2.1, 2.2): Urgent insertions (marked with INSERTED)

Decimal phases appear between their surrounding integers in numeric order.

- [ ] **Phase 2: 軸を決める** - 威力・溜め・CD の釣り合いを**式**にする。3分類の役目を決める

## Phase Details

### Phase 1: 依存を切る

**Goal**: 見本44技を外しても、戦闘も制作ツールも保存個体も壊れん
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: DROP-01〜04, VER-02, VER-03

`starter_moves.js` の44技がどこから参照されとるかを洗う。制作ツールの見本一覧、
技ラボ、戦闘のロスター —— どこが「44本ある」前提で書かれとるか。

**技を捨てるんは Phase 3。** ここでやるんは「捨てられる状態にする」だけ。
空にしても4画面が開いて、にーくらの個体が戦えることを確かめる。

**Success Criteria**

- 44技を空にした状態で、4画面すべてが開いてエラーを出さん
- にーくらの保存個体5体が戦闘に出せて、自作技5本が撃てる
- 内蔵6技だけで検証チェーンが通る
- 依存しとる箇所が記録に残る

### Phase 2: 軸を決める

**Goal**: 威力・溜め・CD の釣り合いが式になり、3分類に別の役目が付く
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: DESIGN-01〜05, VER-01, VER-02, VER-03

**式にするのが肝。** 今は44技それぞれに手で数字が置かれとるだけで、
「なぜこの威力でこのCDか」が誰にも分からん。

軸の候補（実装しながら詰める）:

```
威力とリスクの釣り合い   強い技ほど 溜めが長い or CDが長い
分類ごとの役目          近接 = 踏み込む代わりに避けられん
                        遠距離 = 相殺の土俵に上がる（撃ち合いになる）
                        遠隔 = 相殺されん代わりに溜めが要る
帯                      軽い捨て技（威力10台）〜 大技（威力80以上）
```

**コスト経済（前々マイルストーン）と噛み合わせる。** 大技＝高コストになるけん、
落としたときの損失も大きい。それが「1体も落とさないゲーム」を成立させる。

**反動と間（前マイルストーン）とも噛み合わせる。** 溜めの長い大技があると、
相手に「間を取って避ける」理由ができる。今は溜めが 0.1〜1秒しか無いけん、
避ける値打ちが薄い。

**Success Criteria**

- 式が1箇所にまとまっとって、数字を入れたらCDと溜めが出る
- 3分類それぞれに、他と違う役目が言葉と数字で書かれとる
- 式から外れる技の扱い（例外の書き方）が決まっとる
- 既存の6技を式に当てて、無理が出んか確かめとる

### Phase 2.1: 補助技 (INSERTED)

**Goal**: 補助技が技として成立し、AI が状況を見て撃つようになる
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: SUP-01〜06

**正典は `docs/整理_技一覧の一本化.md` 第4.5節。** ここは要約。

今 `aura` の3本（りゅうのまい・どくどく・うずしお）は**ダメージが0**や。
generator が aura というだけで `applyHit` に到達せんけん、威力をいくつ置いても効かん。
その代わりの補助効果も無い。**絵だけの技が3本ある**、というのが今の姿。

やること6つ:

1. **ステータスの読み口を `statOf()` に寄せる** —— 今16か所で `stats.atk` 等を直に読んどる。
   寄せんと、特性（Phase 17 の `modifyStat` フック）を実装したとき補正系が2つになって競合する。

2. **support 判定を `battle.kind` へ移す** —— generator で判定するのをやめる。
   これだけで aura の3本がダメージを取り戻す。`kind` 未指定は `attack` 扱い（後方互換）。

3. **効果の適用と時間切れ** —— 動かせるのは `atk` / `def` / `eva` / `spd` の4つ。
   `hp` は最大HPが伸び縮みしてゲージが跳ねるけん除外。`int` はにーくら判断で対象外
   （掟16/23 が意図して作った「単純に上げても得やない」ステータスやけん）。
   同じ stat は重ねん（掛け直しは時間が延びるだけ）。試合をまたがん（掟7）。

4. **`scoreMove` に「補助の値打ち」の項** —— **ここが本体。**
   今の採点は期待ダメージが軸やけん、威力0の補助技は0点＋発生の隙のマイナスで
   **AI が一生撃たん**。データだけ増えて死ぬ。
   `dur` 秒で撃てる技の期待ダメージがどれだけ増えるかを見積もって、攻撃技と同じ物差しに乗せる。
   既に同じ強化が乗っとるときは値打ちを落とす（りゅうのまい連打を防ぐ）。
   **AIログに項として出す**（掟9）。

5. **制作ツールの UI** —— 攻撃／補助の切り替えと `effect` の入力。補助のとき威力は伏せる。
6. **回帰ゲート** —— `tools/verify_support.js`。

**⚠ `spd` は「次の技から」効く。** `f.cd[m.id]=m.cooldown*f.cdScale` は撃った瞬間に
計算して固定されるけん、今走っとる反動は縮まらん。UI と AIログで明示すること。

**Success Criteria**

- `aura` の3本が `kind` を付けて撃つとダメージが入る（＝ generator による無力化が消えとる）
- ステータスの読み口が `statOf()` 1本に寄っとって、直読みが残っとらん
- 補助技を撃つと `atk`/`def`/`eva`/`spd` が実際に変わり、`dur` 秒で戻る
- **AI が状況に応じて補助技を選ぶ**。AIログに「補助の値打ち」の項が内訳として出る
- 同じ強化を重ね掛けしても青天井にならん
- 制作ツールで攻撃／補助を切り替えられ、`effect` を入力できる
- `kind` を書いとらん既存の技が1本も挙動を変えとらん

### Phase 3: 補助技を入れる

**Goal**: 補助技が5本あって、AI が戦いの中で実際に撃つ
**Mode:** mvp
**Depends on**: Phase 2.1（仕組み）／Phase 2（軸・数字の根拠として）
**Requirements**: MOVE-01〜05, VER-01, VER-02, VER-03
**Plans:** 1/4 plans executed

Plans:

- [ ] 03-PLAN-CHECK.md
- [x] 03-01-PLAN.md — 既存3本（りゅうのまい・どくどく・うずしお）に `kind`/`effect` を載せ、棚の補助技を実測するゲートを作る（wave 1）
- [ ] 03-02-PLAN.md — 新規2本（すなかけ・斎藤尻隠れ）の専用generatorと専用描画クラスを新造し、非流用ゲートの39決め打ちを解く（wave 2）
- [ ] 03-03-PLAN.md — AI が5本とも撃つことを実走行で数え、CostCalculator で値段を付け、空振りしとった3本のゲートを `workflow.test_command` へ載せる（wave 3）

**Phase 2.1 で機械は組み上がったが、動かす技が1本も無い。**
技棚 191件を数えたら `kind:"support"` は **0本**。りゅうのまい・どくどく・うずしおは
Codex の作り直しで専用 generator を持っとるが、`kind` が付いとらんけん今も攻撃技のまま。
このままやと Phase 2.1 は「動くけど誰も乗っとらん装置」で終わる。

**掟3（専用 generator・素材流用なし）を守る。** 新しく作る2本は専用FXクラスを新造する。
既存素材を組み合わせて「見た目だけ別名」にはせん。

**採点の線を守る。** plan-check R4 で測ったとおり、補助技が攻撃技に採点で勝つには
`delta × dur ≳ 270` が要る。ここを外した技は AI が一生撃たん ——
データだけ増えて死ぬ、という Phase 2.1 が防ごうとした失敗そのものになる。

| 技 | generator | 対象 | 効果 | delta×dur |
|---|---|---|---|---|
| りゅうのまい | `dragon_dance_move`（既存） | 自分 | atk +22 / 16秒 | 352 |
| どくどく | `toxic_move`（既存） | 相手 | atk −20 / 18秒 | 360 |
| うずしお | `whirlpool_move`（既存） | 相手 | spd −20 / 18秒 | 360 |
| すなかけ | 新規専用 | 相手 | eva −20 / 16秒 | 320 |
| 斎藤尻隠れ | 新規専用 | 自分 | def +22 / 16秒 | 352 |

数字は着手時に詰める。**5本目の名前はにーくらが決めた —— 斎藤尻隠れ**（2026-08-21）。
この企画は尻を題材にした技が既にある（ビック尻ドロップ／BigButtDropFX、
tools/verify_butt_animation.js）。その系譜に乗る。

**うずしおの spd− は読み合いとして効く。** `spd` は「次の技から」効くけん、
今走っとる相手の反動は縮まらん。「今すぐ効く技」やのうて「次の一手を鈍らせる技」。

**Success Criteria**

- 補助技が5本あり、`atk`/`def`/`eva`/`spd` の4つと、自分掛け／相手掛けの両方を通っとる
- 5本とも `delta × dur ≳ 270` を満たす
- **AI が実際に5本とも撃つ**。棚に載っとるだけやのうて、戦闘の実走行で発動を数えて確かめる
- 新規2本は専用FXクラスを持ち、既存素材の流用が無い（`verify_rebuilt_moves` と同じ非流用検査）
- 全部 `CostCalculator` を通って値段が付く
- 恒久ゲートに載り、`workflow.test_command` から毎回走る

## 完了条件（このマイルストーン全体）

**にーくらが「この技を使いたい」と思える技が並ぶこと。**

機械で確かめられるんは「式から外れとらん」「AI が実際に撃つ」までで、
**面白いかは人が見るしかない**。作った技で実際に戦わせて決める。
合わんかったら式の定数を触る —— そのために式を1箇所にまとめる。

**このマイルストーンは Phase 3 で終わり**（にーくら決定・2026-08-21）。
技そのものの作り直しは Codex が並行してやり終えた —— made 56本のうち54本が
専用 generator を持ち、汎用素材の流用で残っとるのは にーくら自身の自作
**亜空切断（shatter）と灼熱弾（projectile）の2本だけ**。この2本は掟により
にーくらが触ってええと言うまで手を付けん。
