# Roadmap: ポケット四皇モンスター（反動と間）

## Overview

このマイルストーンが入れるのは、**「撃てん」と「撃たん」を分けて見せる**という一点。

今、外から見て区別が付かん。しかも白い点滅は `charge`（溜め）に使われとって、
にーくらの目にはそれが「反動」に見えた —— **表現と意味がずれとる**。
さらに **AI に「撃たん」という選択肢が無い**。撃てる技があれば必ず撃つ。
だから「相手の攻撃のあとの隙を狙う」という読み合いが、そもそも成立しとらん。

順番には理由がある。**先に中身（状態）を作ってから、見た目を決める**。
見た目を先に変えると、「白＝反動」と覚えた後で「間」が入ったとき、
見分けをもう一度作り直すことになる。にーくらと相談して「まとめて」を選んだ理由がこれ。

`src/sfx_bank.js` は全フェーズを通して不可触。新しい絵は1枚も増やさん（掟4）。
技データ（`starter_moves.js`・保存個体の `customMoves`）には触らん —— 触るのは
`anims.js` の中身と、戦闘側の状態・AI だけ。

## Phases

**Phase Numbering:**

- Integer phases (1, 2, 3): Planned milestone work
- Decimal phases (2.1, 2.2): Urgent insertions (marked with INSERTED)

Decimal phases appear between their surrounding integers in numeric order.

- [ ] **Phase 1: 状態を分ける** - 「反動／間／溜め」を内部で明示的に持ち、ログに出す。**見た目はまだ変えん**
- [ ] **Phase 2: 間を選ばせる** - AI が「撃てるが撃たん」を選べるようにする。回避に備える意味を持たせる
- [ ] **Phase 3: 見た目を分ける** - 反動＝静止＋白点滅／間＝別／溜め＝白を外す。画素で見分けを確かめる

## Phase Details

### Phase 1: 状態を分ける

**Goal**: 今どの状態に居るかが1つの値で読めて、ログに残る
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: STATE-01, STATE-02, STATE-03, VER-02, VER-03

今は状態が散らばっとる —— `f.cd[id]`（技ごとのCD）、`f.actionTimer`（次の行動まで）、
`f.charging`（溜め中）。「反動中か」を知るには全部を見んといかん。

1つの値にまとめる:

```
溜め   f.charging がある
反動   撃てる技が1本も無い（全部CD中）
間     撃てる技はあるが、あえて撃たん   ← Phase 2 で作る
自由   撃てて、撃つ気がある
```

**このフェーズで挙動が変わったら失敗。** 状態を読めるようにするだけで、
誰も何も変えん。既存の検証が全部通ったままであることで示す。

**Success Criteria**
- `stanceOf(f)` のような形で状態が1つの値で取れる
- 状態が変わったときだけログに出る（毎フレーム垂れ流さん）
- `determinismTest()` が通ったまま
- 既存の検証チェーンが全部通ったまま・`sfx_bank.js` は HEAD と一致

### Phase 2: 間を選ばせる

**Goal**: AI が「撃てるが撃たん」を選び、その間に回避できる
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: MA-01〜05, STATE-02, VER-01, VER-02, VER-03

`pickMove` は今、撃てる技から必ず1つ返す。ここに「撃たん」を候補として足す。

間を取る理由の候補（実装しながら絞る）:

- 相手が溜め中 —— 撃つより避けた方がよいことがある
- 相手の技が全部CD中 —— 今は安全。急いで撃つ理由が薄い
- 自分のHPが薄い —— 一発もらったら落ちる場面で突っ込まん
- 手持ちのコストが高い —— 落としたら経済が壊れる（前マイルストーンの成果が効く）

**賢さ（int）と慎重さ（caut）で寄せる**（掟：賢さは有利にも不利にも働く）。
馬鹿は間を取らんし、慎重すぎる個体は撃つべきときに撃たん。
**極端に寄らんこと**を実戦で数えて示す。

**掟1（決定論）** を壊さんこと。間を取るかどうかも `battleRng` を通す。
**掟9（AIログ）** —— 何を見て間を取ったかがログに残らんと、調整できん。

**Success Criteria**
- 撃てる技があるのに撃たん場面が実戦で発生する
- 間を取った理由がログに出る
- 間の最中に回避が起きる（攻撃中はできんことと対になる）
- 「常に間」「絶対間を取らん」に寄っとらん（試合を回して数える）
- `determinismTest()` が通ったまま

### Phase 3: 見た目を分ける

**Goal**: 見とる人が「撃てん／撃たん／溜めとる」を見分けられる
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: LOOK-01〜05, KEEP-01〜03, VER-01, VER-02, VER-03

にーくらの指定:

```
反動（CD）  静止させながら白く点滅       ← 今 charge が持っとる表現をここへ
間          白やない別の表現。構えとるのが分かる
溜め        白を外す。反動と見分けが付くこと
```

**既存を壊さんことが枷になる。** 変えるんは `anims.js` の `charge` の中身だけで、
**割り当て（分類→anim名）は変えん**。`motions` を自前で書いとる技は既定に来んけん、
何をしても無影響 —— それを数えて示す。

**Success Criteria**
- 3つの状態が画素で見分けられる（目視に頼らん）
- `motions` 自前の技が1つも変わっとらん
- 分類→anim の割り当て表が変わっとらん
- 新しい画像ファイルが増えとらん（掟4）
- にーくらの保存個体の自作技が撃てて当たって鳴る

## 完了条件（このマイルストーン全体）

**にーくらが試合を見て、「今こいつは撃てんのやな」「今は様子見しとるな」が分かること。**

機械で確かめられるんは「状態が分かれとる」「見分けが付く絵になっとる」までで、
**読み合いとして面白いかは人が見るしかない**。面白くなかったら、
間を取る条件と重み（int / caut の効き方）を触って調整する。
そのために条件と重みは1箇所にまとめる。
