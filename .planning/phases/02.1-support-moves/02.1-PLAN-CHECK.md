## 1. BLOCKER

### B1. 補助の値打ちの式が、設計書自身の例の値では**攻撃に絶対勝てん**。誰も確かめん

`02.1-01-PLAN.md` Task 1 手順5

Plan の式（そのまま）:

    buffValue = refMove.power * (delta/100) * mit * qb * stab
              * (dur / (refMove.cooldown * cdScale)) / defender.maxHP * 140

現行定数で手計算した（`statOf` はまだ無いけん実測やのうて**式の評価**。前提: 両者オール50、
`maxHP=120`、参照技=灼熱弾 `power26/cast0.30/cd2.4`、補助技=設計書4.5-2の例
`power0/cast0.6/cd6.0/atk+15/dur8/self`、quarter<=4、STAB無し）:

| 項 | 攻撃（灼熱弾） | 補助（設計書の例） |
|---|---|---|
| 期待ダメージ | 26x1.0x(100/150)=17.33 → dr .1444 → **20.2** | 0 |
| 補助の値打ち | — | 26x0.15x.667=2.6 → /120=.0217 x(8/2.7=2.96)=.0642 x140 = **9.0** |
| 手数 | (2.6/2.7)x9 = **8.7** | (2.6/6.75)x9 = **3.5** |
| 発生の隙 | -0.30x38 = **-11.4** | -0.60x38 = **-22.8** |
| 好機（read .5） | +4.8 | +9.7 |
| **合計** | **≒ 22.3** | **≒ -0.6** |

**差23点。** 一般形にすると（atk=50 のとき）
`補助の値打ち / 期待ダメージ = (delta/100) x N`、`N = dur/(cd x cdScale)`。
つまり**「1発殴るより得」になるには `delta x N >= 100`**。delta+15 なら N>=6.7 → cd2.4 の技で **dur>=18秒**が要る。
設計書の例（delta15/dur8）は N=2.96 → 殴り**1発の44%**。Plan 01 の検証が使う値（delta+20/dur8）でも **59%**。
`scoreMove` は「間（`scoreHold`）」とも競うけん、実際はもっと不利。

唯一の摘み（`SUPPORT_W.scale=140`）は「dmgV と同じ物差しやけん」で置いただけで、
**どの Plan にも「勝つ状況が実在するか確かめて、無ければ定数を直す」工程が無い。**
このまま出すと「項はあるが一生効かん」＝フェーズの目的（AI が状況を見て撃つ）が未達のまま緑になる。

**直し方**: (a) ゲートで**順位**を主張する（B2）、(b) 落ちたら `SUPPORT_W.scale` か効果レンジを実測で較正する工程を Plan に入れる、(c)「撃つ＝1手を捨てる」機会費用を式に入れるか `dur` の下限を上げる。

### B2. ゲートが「効いとる項」と「死んだ項」を**見分けられん**

`02.1-01-PLAN.md` Task 1 手順7 / `02.1-03-PLAN.md`

Plan の主張は2つ:

- (a)「`pickMove()` が少なくとも1回この技を選ぶ」
- (b)「AIログの `補助の値打ち` が `|v|>=0.05`」

`tempOf` は `1.2+(100-int)*0.34` = int50 で **T≒18.2**。softmax の温度がこれやと、
**23点差でも p≒0.22 で選ばれる**。上の数字で言うと、補助の値打ちが**丸ごと0でも p≒0.15** ——
つまり (a) は項が全く動いとらんでも通る。(b) の閾値 0.05 は `T()` が項を捨てん最小値そのもので、
「9.0点」も「0.06点」も同じく合格。**両方通っても B1 の状態を検出できん。**

ROADMAP の文言は「**状況に応じて**選ぶ」。状況依存は今どの Plan でも一切測っとらん。

**直し方**: 順位で主張する。

1. 有利な場面（`foeBusy(foe)` true・両者HP満）で **`scoreMove(support).total > 全攻撃技の total`**
2. 不利な場面（相手を1発で落とせる＝`とどめ` が乗る）で **support が負ける**
3. `補助の値打ち` が `delta` と `dur` に対して単調に増える（式が繋がっとる証明）

`|v|>=0.05` は「項が存在する」チェックであって「値打ちがある」チェックやない。

### B3. 相手に掛ける弱化の符号が逆。AI は弱化技を**避けるようになる**

`02.1-01-PLAN.md` Task 1 手順5・Task 2 / `02.1-02-PLAN.md` Task 1

Plan は `buffValue` を「**強化された側**の期待ダメージの増分」として定義しとる
（using refAtkMove of the attacker = the buffed fighter）。符号の反転がどこにも書いとらん。

`effect={stat:"atk", delta:-20, target:"foe"}`（相手の攻撃を下げる＝こっちに得）を入れると:
attacker=相手、delta 負 → `buffValue` は**負** → `T("補助の値打ち", 負)` が f の点に足される → **撃たんようになる**。
`def` 枝も同じ（Task 2 は「buffed fighter への被ダメが減れば正」と定義しとるけん、相手の def を下げると負）。

`target: self/foe` は設計書4.5-2の表にある canon で、**Plan 02 はその入力UI（自分/相手）を作る**。
つまり「作れるのに AI が嫌がる技」が半分できる。検証も全部 self しか触っとらん。

**直し方**: 値打ちを「**f から見た**期待ダメージ収支」に統一する
（Δ(f の与ダメ) - Δ(foe の与ダメ)）。そうすれば self/foe も +delta/-delta も符号が自然に出る。
そのうえで相手掛けのケースをゲートに1本足す。

### B4. 重ね掛けの仕様が Plan 内で**自己矛盾**しとる

`02.1-01-PLAN.md` Task 1 手順4 と Task 2 の検証

- Task 1: 「`target.buffs[stat] = {delta:effect.delta, until:...}` — **plain overwrite**」
- Task 2: 「delta の**違う**値で2回撃って、`buffs.atk.delta` が**最初の cast の delta のまま**であることを assert」

overwrite なら delta は2回目の値になる。**この2つは同時に成立せん。** 実行者は片方を勝手に曲げる。
canon は「掛け直したら**時間が延びるだけ**（`delta` は加算せん）」（設計書4.5-2）＝ delta 据え置き・`until` 更新、と読める。
ついでに overwrite は `until` も上書きするけん、**dur の短い技を上掛けすると効果時間が縮む**（「延びるだけ」に反する）。

**直し方**: 1つに決めて両方へ書く。推奨は
`buffs[stat] = {delta: 既存があれば据え置き, until: Math.max(既存until, battleTime+dur)}`。

`02.1-02-PLAN.md`（`normalizeMon` に一切触れとらん）

### B6. 補助技を撃つと、**撃った本人が自分の技を回避しようとする**

どの Plan にも記述無し（`battle.tpl.html:1643` / `:1912-1920` / `tryDodge:1831`）

    sh.forSide = support ? f.side : foe.side;          // :1643
    ...
    const def = s.forSide==="ally"?ally:enemy;         // :1916 → 補助弾では def = 撃った本人
    if(def===atk){ ...continue; }                      //        → 通り抜ける
    tryDodge(def,s,atk);                               // :1920

`tryDodge` に**自分の弾を除外する門番が無い**（`pushSub` は `forSide="none"` ＋ `dodgeChecked=true` で
素材を外しとるのに、本体の補助弾は外れとらん）。成功すると（prob は最大0.95）:

- `f.dodgeUntil=battleTime+0.55` … **無敵0.55秒がタダで付く**（`buffValue` は勘定に入れとらん）
- `if(f.charging){ f.charging=null; f.actionTimer=0.5; }` … **自分の次の溜めを自分で潰す**
- `playSys("dodge")` ＋「○○は　かわした！」…**嘘のメッセージ**

これは aura の3本で**既に起きとる**既存バグやが、このフェーズは (1) その3本を attack へ戻して症状を消し、
(2) 代わりに **AI が日常的に撃つ補助技**を新設する。つまり**この phase が初めてこれを常態化させる**。
「補助技が技として成立し」という目標の直撃やけん、ここで閉じる。

**直し方**: `launch()` の support 枝で `sh.dodgeChecked=true; sh.forSide="none";`（素材と同じ扱い）にするか、
:1916 のループに `if(s.owner===def){ s.dodgeChecked=true; continue; }` を足す。
ついでに `stepClash()` は `a.forSide===b.forSide` で弾くけん、**自分の補助弾と自分の攻撃弾は forSide が違う** ——
projectile 系の補助技を作ると**自分の弾同士が相殺する**（発射点が同じ `muzzle(f)` やけん距離0で即成立）。
同じ修正で消える。
