## Decisions Made
- **合成した決定論試験用の補助技は `makeSpec('aura', seed, name, type)` を使う**（素の `{generator:'aura', motions:[]}` ではない）。既存の2a/2b/2c等は `scoreMove()` を直接呼ぶだけでAuraFXの実体化を通らんが、`determinismTest()` は `stepBattle()` 経由で実際にFXを走らせるけん、`palette` を欠いた素のfxオブジェクトだと `AuraFX.update` が `s.palette.length` で例外を投げる。1回実際に踏んで検出し、B7の`probe`技と同じパターン（`makeSpec`）へ揃えて解決した。
- **`applySupportEffect` を一時的にカウンタ付き関数へ差し替えて呼び出し回数を数える**——「movelistに合成技が載っとる」だけでは「実際にキャストされた」証拠にならん。determinismTest()自体は使用技の統計を返さんため、round-2 R2チェックが `effDelta` をモンキーパッチしたのと同じ手口を、本番関数の呼び出し回数カウントという形で決定論チェックにも展開した。
- **workflow.test_command に `node tools/verify_creator.js` も追加した**（プランが明示的に要求したのは`verify_support.js`のみ）。理由はオーケストレーターの明示指示（NGSD掟7 空振りしたゲート）：Plan 02（コミット`ae8c3e8`）が `tools/verify_creator.js` へB5/B8の実アサーション（`ok(cond,msg)`機構）を追加したが、`npm run verify:creator` スクリプトは既にpackage.jsonにあったのに `workflow.test_command` には登録されておらず、恒久回帰ゲートとして一度も自動で走っとらんかった。存在するが発火しないゲートは無いのと同じであり、これはPlan 02の仕事の直接の完成である。`tools/verify_creator.js` 自体のコード変更は不要——`test_command`への1行登録のみ。
- **`package.json` の `verify:support` は意図的に未コミット**。共有ワーキングツリーでこのファイルを同時編集中のCodexが、自分の変更と一緒にgitへ入れる取り決め（にーくら経由で合意済み）。`workflow.test_command` はこの未コミット行に依存させず、`npm run verify:support` ではなく `node tools/verify_support.js` の直呼び形にした——恒久ゲートが未コミットのpackage.json行の運命と無関係に機能する。
