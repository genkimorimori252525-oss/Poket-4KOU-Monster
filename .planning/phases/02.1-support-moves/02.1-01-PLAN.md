<objective>
Make 補助技 (support moves) a real mechanism in `src/battle.tpl.html`: one funnel function for
every gameplay stat read (`statOf`), a data-driven `kind` field replacing the `fx.generator==='aura'`
check that currently hardcodes zero damage on 3 library moves, an effect-apply/expire system for
`atk`/`def`/`eva`/`spd`, and — the actual point of the phase — a scoring term so the battle AI can
see a support move is worth casting and picks it in `scoreMove()`/`pickMove()`.

Purpose: today `aura`-generator moves always deal 0 damage (generator-based bug) and there is no
mechanism at all for a move to buff a stat mid-match. Without a scoring term, the AI — which is
the only thing that ever picks a move in this game, per CLAUDE.md — will never choose a `power:0`
support move over an attack move; a support move with no scoring term is dead data.

Output: `statOf()` as the single read path for all 6 stats (16-17 direct-read call sites migrated),
`kind`/`effect` as flat fields on the runtime move object (NOT nested under `.battle` — see the
architecture note below), the buff apply/expire system, the scoreMove term, and
`tools/verify_support.js` proving the AI actually picks a support move with a visible log breakdown.
</objective>
