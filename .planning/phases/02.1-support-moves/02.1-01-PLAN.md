**4. buffValue — symmetric, on the same yardstick as `期待ダメージ` (closes B1 and B3 together).**
Add near `scoreMove`. Four small helpers, then one dispatcher:
- `effDelta(base, delta) = Math.max(1, Math.min(100, Math.round(base+delta))) - base` — the SAME
  1-100 ceiling `statOf` applies, computed once and reused everywhere a raw `delta` would otherwise
  be added unclamped (closes plan-checker round-2 R2). Without this, a support move on a high-stat
  individual overstates its own value, routinely, not as an edge case — にーくらの既定ロスターは
  6体中3体が何かのステータスで75を超えとる（パルキア atk92、いわもどき def80、かげもどき
  spd88/eva84）。`atk+25` を掛けても、`statOf` が実際に返す上限は100やけん、パルキア(atk92)には
  本当は`+8`しか乗らんのに、`delta`を生のまま値踏みしたら3.1倍の過大評価になる（測定値: dur:20の
  自分掛けatkバフで、天井を見ん場合40.56点・見た場合12.98点、対戦相手ルギアもどき基準）。
  これはスコアの誤りだけやのうて掟9違反でもある — AIログが40.6点と表示して、実際は13.0点しか
  効いとらんかったら、内訳が嘘をついとることになる。
- `rawFlow(attacker, defender, statSlot, delta, dur)`: the raw expected damage `attacker` deals
  `defender` over `dur`, using `attacker`'s `refAtkMove` (see below), with `delta` applied through
  `effDelta` per `statSlot`: `'atk'` raises attacker's atk by
  `effDelta(statOf(attacker,'atk'), delta)` in the `0.5+atk/100` term; `'spd'` instead recomputes
  attacker's `cdScale` at `statOf(attacker,'spd') + effDelta(statOf(attacker,'spd'), delta)`
  (`1.55-spd/100*0.85`), changing the hits count rather than the per-hit magnitude; `'def'` raises
  DEFENDER's def by `effDelta(statOf(defender,'def'), delta)` in the `100/(100+def)` mitigation
  term. **The hits count itself is also capped to the live time actually remaining before the next
  quarter interval (closes plan-checker round-2 R3).** `stepBattle` advances `battleTime` BEFORE its
  `if(phase==='interval') return;` early exit, so an 8-second interval burns buff duration with zero
  attacks happening during it — `QUARTER={len:20,interval:8}` means a `dur:20` buff cast anywhere
  but the exact top of a quarter runs into dead time. The existing global `phaseLeft` (`let
  phase='battle', phaseLeft=QUARTER.len;`) already tracks time left in the current phase, so: `const
  usable = Math.max(0, Math.min(dur, phaseLeft)); const hits = usable/(refMove.cooldown*cdScale);`.
  This is a deliberate simplification (it only accounts for time left in the CURRENT phase, not
  whatever survives into the next battle phase after the interval ends) but it's a one-line fix that
  buys the situational behavior this phase is actually for — casting at the top of a quarter is
  worth more than casting into an interval, for free. Formula:
  `refMove.power*(0.5+attackerAtk/100)*100/(100+defenderDef)*quarterBonus()*hits`. Deliberately NO
  `stabOf` factor and NO dodge-probability factor — `期待ダメージ` itself is `dr/st*140` (STAB
  divided back out into a separate `タイプ一致` term) and never discounts for dodge either;
  `buffValue` must stay on that same yardstick or it silently over/under-values relative to what an
  attack move's own score already represents (the first draft's `N1` finding). Return 0 if
  `attacker` has no `refAtkMove`.

⚠ **Once the ceiling fix above is in, the ordering assertions in step 6 get harder to satisfy than
they were against the unclamped (buggy) formula. The obvious-looking response is to raise
`SUPPORT_W.scale` to compensate. Do not.** That is the exact move this plan already refused once
(the original B1/round-2 R4 finding), and it would be wrong for the same reason here: raising the
scale to compensate for a ceiling correction does not fix a miscalibration, it just re-introduces
the same over-valuation the ceiling fix exists to remove, moved onto a different knob, and it would
do so for EVERY support move on EVERY roster member, not just the one that happened to fail a test.
If a specific calibration scenario stops winning once the ceiling is correctly applied, the fix is
to change that scenario's `delta`/`dur`/cast/cooldown (as this plan already does below — the
calibration is pinned to all-50 stats, where `atk+25` lands at `75`, well inside the 1-100 range, so
`effDelta` never actually clamps anything there and the ceiling fix changes NONE of the numbers in
the calibration below). Verify that stays true rather than assuming it — it's asserted explicitly in
step 6's pinned scenario, not left implicit.
- `offenseFlow(attacker,defender,statSlot,delta,dur) = rawFlow(...,delta,dur) - rawFlow(...,0,dur)`
  — the signed marginal change versus the zero-delta baseline, same `dur` window both times.
- `evaFlow(recipient,attacker,delta,dur) = -rawFlow(attacker,recipient,'atk',0,dur) *
  (effDelta(statOf(recipient,'eva'), delta)*0.62/100)` — eva never appears in `damageOf` at all, its
  only lever is `tryDodge`'s own `T('基礎回避力', statOf(f,'eva')*0.62)` slope, so it needs this
  separate shape (a fraction of the attacker's raw baseline output over the same usable window,
  signed negative for a positive delta — "less damage now gets through", matching how a positive
  `def` delta also produces a negative flow). Also routed through `effDelta` — eva's own downstream
  use (`tryDodge`'s dodge PROBABILITY) has its own separate `[0.02,0.95]` clamp, but the eva STAT
  itself is still capped 1-100 by `statOf` first, same ceiling property as atk/def/spd.
- `refAtkMove(who)`: the lowest-`cooldown` move in `who.moves` where `!isSupportMove(mv)`, or `null`.
- `hasBuff(who,stat)`: true if `who.buffs[stat]` exists and `battleTime < who.buffs[stat].until`.
- `SUPPORT_W = {scale:140, decay:0.15}` (matching `HOLD_W`'s centralized-tunable style).
- `buffValue(f, foe, effect)`: resolve `target = effect.target==='foe'?foe:f`. Exactly one of
  `dFlowToFoe`/`dFlowToF` is nonzero per call — this single dispatch table is what makes every
  self/foe and buff/debuff sign combination come out correct with NO per-case sign flip anywhere
  else (this is the actual fix for B3 — the first draft's formula only ever measured "the buffed
  fighter's own gain" and never flipped sign for a foe-targeted debuff):
  - `effect.stat` is `'atk'` or `'spd'` (target's own offense changes): if `target===f`,
    `dFlowToFoe = offenseFlow(f,foe,effect.stat,effect.delta,effect.dur)`; if `target===foe`,
    `dFlowToF = offenseFlow(foe,f,effect.stat,effect.delta,effect.dur)`.
  - `effect.stat` is `'def'` (target's own mitigation changes what it takes): if `target===f`,
    `dFlowToF = offenseFlow(foe,f,'def',effect.delta,effect.dur)`; if `target===foe`,
    `dFlowToFoe = offenseFlow(f,foe,'def',effect.delta,effect.dur)`.
  - `effect.stat` is `'eva'` (same flow direction as `'def'`, different helper): if `target===f`,

    `dFlowToFoe = evaFlow(foe,f,effect.delta,effect.dur)`.
  Then `net = dFlowToFoe/foe.maxHP - dFlowToF/f.maxHP` (more damage flowing toward foe is good for
  f; more flowing toward f is bad — this single formula is what auto-corrects every sign case, no
  further per-branch flipping needed). `buffValue = net * SUPPORT_W.scale * (hasBuff(target,
  effect.stat) ? SUPPORT_W.decay : 1)` — check `hasBuff` on the RESOLVED `target`, not always `f`
  (the exact bug B3 flagged in the first draft's decay check).
