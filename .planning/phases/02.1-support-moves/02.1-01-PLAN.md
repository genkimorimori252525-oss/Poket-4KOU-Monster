the caster no longer rolls to dodge its own support shot (which was granting a free 0.55s dodge

and a support shot from one move can no longer clash-collide with an attack shot from the same

**4. buffValue — symmetric, on the same yardstick as `期待ダメージ` (closes B1 and B3 together).**
Add near `scoreMove`. Three small helpers, then one dispatcher:
- `rawFlow(attacker, defender, statSlot, delta, dur)`: the raw expected damage `attacker` deals
  `defender` over `dur`, using `attacker`'s `refAtkMove` (see below), with `delta` applied per
  `statSlot`: `'atk'` raises attacker's atk in the `0.5+atk/100` term; `'spd'` instead recomputes
  attacker's `cdScale` at `spd+delta` (`1.55-spd/100*0.85`), changing `hits=dur/(refMove.cooldown*
  cdScale)` rather than the per-hit magnitude; `'def'` raises DEFENDER's def in the `100/(100+def)`
  mitigation term. Formula: `refMove.power*(0.5+attackerAtk/100)*100/(100+defenderDef)*
  quarterBonus()*hits`. Deliberately NO `stabOf` factor and NO dodge-probability factor —
  `期待ダメージ` itself is `dr/st*140` (STAB divided back out into a separate `タイプ一致` term) and
  never discounts for dodge either; `buffValue` must stay on that same yardstick or it silently
  over/under-values relative to what an attack move's own score already represents (the first
  draft's `N1` finding). Return 0 if `attacker` has no `refAtkMove`.
- `offenseFlow(attacker,defender,statSlot,delta,dur) = rawFlow(...,delta,dur) - rawFlow(...,0,dur)`
  — the signed marginal change versus the zero-delta baseline, same `dur` window both times.
- `evaFlow(recipient,attacker,delta,dur) = -rawFlow(attacker,recipient,'atk',0,dur) * (delta*0.62/100)`
  — eva never appears in `damageOf` at all, its only lever is `tryDodge`'s own
  `T('基礎回避力', statOf(f,'eva')*0.62)` slope, so it needs this separate shape (a fraction of the
  attacker's raw baseline output, signed negative for a positive delta — "less damage now gets
  through", matching how a positive `def` delta also produces a negative flow).
- `refAtkMove(who)`: the lowest-`cooldown` move in `who.moves` where `!isSupportMove(mv)`, or `null`.
- `hasBuff(who,stat)`: true if `who.buffs[stat]` exists and `battleTime < who.buffs[stat].until`.
- `SUPPORT_W = {scale:140, decay:0.15}` (matching `HOLD_W`'s centralized-tunable style).
- `buffValue(f, foe, effect)`: resolve `target = effect.target==='foe'?foe:f`. Exactly one of
  `dFlowToFoe`/`dFlowToF` is nonzero per call — this single dispatch table is what makes every
  self/foe and buff/debuff sign combination come out correct with NO per-case sign flip anywhere
  else (this is the actual fix for B3 — the first draft's formula only ever measured "the buffed
  fighter's own gain" and never flipped sign for a foe-targeted debuff):
  - `effect.stat` is `'atk'` or `'spd'` (target's own offense changes): if `target===f`,
    `dFlowToFoe = offenseFlow(f,foe,effect.stat,effect.delta,effect.dur)`; if `target===foe`,
    `dFlowToF = offenseFlow(foe,f,effect.stat,effect.delta,effect.dur)`.
  - `effect.stat` is `'def'` (target's own mitigation changes what it takes): if `target===f`,
    `dFlowToF = offenseFlow(foe,f,'def',effect.delta,effect.dur)`; if `target===foe`,
    `dFlowToFoe = offenseFlow(f,foe,'def',effect.delta,effect.dur)`.
  - `effect.stat` is `'eva'` (same flow direction as `'def'`, different helper): if `target===f`,
    `dFlowToF = evaFlow(f,foe,effect.delta,effect.dur)`; if `target===foe`,
    `dFlowToFoe = evaFlow(foe,f,effect.delta,effect.dur)`.
  Then `net = dFlowToFoe/foe.maxHP - dFlowToF/f.maxHP` (more damage flowing toward foe is good for
  f; more flowing toward f is bad — this single formula is what auto-corrects every sign case, no
  further per-branch flipping needed). `buffValue = net * SUPPORT_W.scale * (hasBuff(target,
  effect.stat) ? SUPPORT_W.decay : 1)` — check `hasBuff` on the RESOLVED `target`, not always `f`
  (the exact bug B3 flagged in the first draft's decay check).
