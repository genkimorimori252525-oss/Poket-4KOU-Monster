## 5本の数字と、`delta × dur ≳ 270` をどの前提で判定するか

にーくらが決めた表（03-CONTEXT.md「作る5本」・**変更不可**）:

| 技 | generator | 対象 | 効果 | delta×dur |
|---|---|---|---|---|
| りゅうのまい | `dragon_dance_move`（既存） | 自分 | `atk +22` / 16秒 | 352 |
| どくどく | `toxic_move`（既存） | 相手 | `atk −20` / 18秒 | 360 |
| うずしお | `whirlpool_move`（既存） | 相手 | `spd −20` / 18秒 | 360 |
| すなかけ | `sand_attack_move`（新規） | 相手 | `eva −20` / 16秒 | 320 |
| 斎藤尻隠れ | `saito_butt_hide_move`（新規） | 自分 | `def +22` / 16秒 | 352 |

### 判定の前提（ここを曖昧にしたら測れん）

**`delta × dur ≥ 270` は「名目値」で判定する。** `effect.delta` と `effect.dur` そのもの。
5本とも `effect` に書いた値で 320〜360 やけん、無条件に満たす。

**実効値では判定せん。** `src/battle.tpl.html:1414` の `effDelta` が
`statOf` の 1〜100 天井（`:1218`）を通すけん、**個体によって実効が変わる**：

- 全50の個体に `atk+22` → 実効 +22（50+22=72、天井に当たらん）
- パルキア（`src/battle.tpl.html:929`、atk 92）に `atk+22` → 実効 **+8**（100で頭打ち）

同じ技が個体によって 352 にも 128 にもなる。**技の合否を個体で決めたらいかん。**
だから線は名目で引き、**実効のほうは較正シナリオで測って表に出す**（下）。
これは 02.1 の plan-check R2 が突いた食い違いと同じ形やけん、役割を分けて両方持つ。

### 較正シナリオ（実効の測り場）

`tools/verify_support.js:139` の `window.__pin(f,foe)` をそのまま使う。中身は
**f=enemy・foe=ally、両者の stats/per を全50、foeBusy は `foe.actionTimer=1.0` だけで作る**
（02.1 plan-check round-2 R1 の是正）。全50なら 50±25 が 25〜75 に収まるけん
**天井クランプが1度も効かん**——名目＝実効の領域。ここで測るけん実効の食い違いが混ざらん。

参照は 灼熱弾（power 26 / cast 0.30 / cd 2.4）。この場面での総合点は **22.33**
（02.1 が実測、`tools/verify_support.js:203` が今も assert しとる）。

### 机上の見積り（**着手時に実測して確かめること**。貼るな、測れ）

較正シナリオを Node で組み直して計算した投影値。`灼熱弾 total=22.33` を再現できとるけん
モデル自体は合っとるはずやが、**これは仮説や。ゲートが出す実測値が正。**

| 技 | delta×dur | 補助の値打ち（投影） | cast / cd（このプランで置く値） | 総合点（投影） |
|---|---|---|---|---|
| りゅうのまい | 352 | 26.4 | 0.35 / 4.5 | 23.3 |
| どくどく | 360 | 28.8 | 0.40 / 6.0 | 23.6 |
| うずしお | 360 | 18.9 | 0.25 / 3.0 | 20.4 |
| すなかけ | 320 | 14.9 | 0.25 / 3.0 | 16.3 |
| 斎藤尻隠れ | 352 | 16.4 | 0.35 / 4.0 | 13.9 |

総合点の式（較正シナリオ・全50）: `20.8/cd − 21.85×cast + 補助の値打ち`
（手数 `(2.6/(cd×1.125))×9`、発生の隙 `−cast×38`、好機 `+cast×38×0.85×0.5`）。

**分かったこと（重要）**: R4 の「270」は
**`atk`・自分掛け・`atk` 効果**の一般形から出た線や（02.1-PLAN-CHECK.md:57-63）。
`spd`/`eva`/`def` は `delta×dur` あたりの換算率が `atk` の 6〜7割しか無い
（実測の裏付け: 02.1-PLAN-CHECK.md:76-84 の16通り表。dur10・±20 で
atk 14.98 / def 11.52 / spd 9.83 / eva 9.29）。
だから **270 を満たしても 灼熱弾 に総合点で勝つとは限らん。**

### ここでどう振る舞うか（**勝手に数字を膨らません**）

1. **まず にーくらの表のとおりに置く。** 上の cast/cd で実装する。
2. **測る。** 較正実測表をゲートのログに出す（Task 3）。
3. **AI が実際に撃つかを実走行で数える**（Plan 03 の MOVE-03 ゲート）。
   softmax の温度は int50 で `T=1.2+50*0.34=18.2`（`src/battle.tpl.html:1572` tempOf）と
   かなり熱いけん、**2〜4点負けとる技でも普通に選ばれる**。総合点で勝つことは要件やない。
4. **実走行で1度も撃たれん技があったときだけ**、その技の数字を段階的に上げる:
   - 段1: `dur` を 20 へ（上限）
   - 段2: `|delta|` を 25 へ（上限。自分掛けは +25、相手掛けは −25）
   緑になった段で止める。**`SUPPORT_W.scale`（`src/battle.tpl.html:1476`）は触らん**
   —— 02.1 が意図して据え置いた定数で、上げると天井補正（R2）を無意味にする。
5. **`delta×dur` を 270 未満へ下げることは絶対にせん。** にーくらの決定。

段を上げたときは **SUMMARY に「どの技を・なぜ・実測いくらから いくらへ」を必ず書く。**
