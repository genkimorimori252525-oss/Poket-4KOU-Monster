## v4 Requirements

### 依存を切る（DROP）

技を捨てる前に、**捨てても壊れんこと**を先に確かめる。順番を逆にしたら、
何が原因で壊れたか分からんくなる。

- [ ] **DROP-01**: 見本技44本を外しても、戦闘・制作ツール・4画面が壊れん
- [ ] **DROP-02**: にーくらの保存個体（5体）と自作技（5本）が無傷。撃てて当たって鳴る
- [ ] **DROP-03**: 内蔵6技は残る —— 戦闘の土台やけん、ここまで抜いたら検証が回らん
- [ ] **DROP-04**: 44本に依存しとる箇所が洗い出されて、記録に残る

### 設計の軸（DESIGN）

**式にする。** 「なんとなく強そう」で数字を置いたら、次に技を足す人が同じ迷いをする。

- [ ] **DESIGN-01**: 威力・溜め・CD の釣り合いが**式**として書かれ、1箇所にある
- [ ] **DESIGN-02**: 3分類（近接／遠距離／遠隔）それぞれに**別の役目**がある。名前だけの分類にせん
- [ ] **DESIGN-03**: 威力の帯が広い —— **軽い捨て技から大技まで**。コスト経済の「格上を食う」が効く幅
- [ ] **DESIGN-04**: 相殺・回避・反動・間が**意味を持つ**組み合わせがある
- [ ] **DESIGN-05**: 式から外れた技（例外）は、外れとる理由が書いてある

### 新しい技（MOVE）

- [ ] **MOVE-01**: 軸に沿った技が揃う。**数より意味** —— 使い道が説明できん技を並べん
- [ ] **MOVE-02**: 全部 `CostCalculator` を通って値段が付く。不当に安い技が無い（計画18.5 の三重取り）
- [ ] **MOVE-03**: 3分類に偏りなく配られとる
- [ ] **MOVE-04**: 相殺の土俵（遠距離同士）で、力関係が実際に決まる組み合わせがある
- [ ] **MOVE-05**: 溜めの長い大技があって、**それが「間」を取る理由になる**

### 補助技（SUP・Phase 2.1、INSERTED）

- [x] **SUP-01**: ステータスの読み口が `statOf()` 1本に寄っとって、直読みが残っとらん

- [x] **SUP-03**: 補助技の効果（`atk`/`def`/`eva`/`spd`）が実際に効いて `dur` 秒で切れる。試合をまたがん
- [x] **SUP-04**: `scoreMove` に補助の値打ちの項があって、AI が状況に応じて補助技を選ぶ
- [ ] **SUP-05**: 制作ツールで攻撃／補助を切り替えられ、`effect` を入力できる
- [ ] **SUP-06**: `tools/verify_support.js` が回帰ゲートとして走り、`workflow.test_command` に入っとる
