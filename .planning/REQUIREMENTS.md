## v2 Requirements

### CostCalculator の独立（COST）

計画18.5 に警告がある ——「コストは**損失額と獲得額の両方**を決めるようになった。
不当に安く見積もられた個体は『強い』『死んでも痛くない』『刺客ボーナスが大きい』を
**三重取り**する。確実に壊れる」。だから式を差し替えられる形にしてから経済を載せる。

- [x] **COST-01**: コスト算出が `src/cost.js` として独立し、式を書き換えても呼び出し側を1行も触らんで済む
- [x] **COST-02**: 今 `costOf` を通っとる全ての呼び出しが新モジュールを見る。**差し替えの前後で全個体のコストが1も変わらん**（同じ入力に同じ数字）
- [x] **COST-03**: 算出の内訳（base / mv / avg）が取り出せて、なぜその値になったか追える（掟9：内訳が見えん実装をしない）

### 所持コスト＝陣営の体力（ECON）

- [x] **ECON-01**: 試合開始時、両陣営が所持コスト **150** を持つ。上限は **300**（初期値の2倍）
- [x] **ECON-02**: 味方が戦闘不能になると、所持コストから**その個体のコスト全額**が引かれる
- [x] **ECON-03**: 敵を倒すと `相手のコスト × min(2.0, 相手のコスト ÷ 倒した個体のコスト) × 0.5` が加算される
- [x] **ECON-04**: 計画18.3 の計算例3つが、実装でその通りの数字になる（20が140を倒す=**+140** / 50が50=**+25** / 140が20=**+1.4**）
- [x] **ECON-05**: 所持コストの増減が AIログに残る。いつ・誰が・いくら動いたかが後から追える（掟9）
- [x] **ECON-06**: 所持コストを入れても決定論が壊れん。同じ種で同じ結果になる（掟1）
- [x] **ECON-07**: 係数k（0.5）・比率上限（2.0）・初期値（150）・上限（300）が1箇所にまとまっとって、触って試せる

## Out of Scope

このマイルストーンでは**やらん**もの。

- **コスト上限で編成を制限する** —— 掟6 で禁じられとる。コストは編成枠やない
- **本式の CostCalculator** —— 仮の式のまま実戦検証する。それが計画18.5 の指示（前倒しの理由そのもの）
- **特性（Phase 17）** —— コスト算出の考慮対象やが、まだ存在せん。フックだけ空けておく
- **死亡の作り込み（Phase 16）** —— 試合内限定の死亡・復帰禁止は次。今は HP0 の既存処理に乗る
- **伸びしろ・育成（Phase 22）** —— 計画が「最後に実装する」と明記しとる

## 完了条件（計画 Phase 15 の原文）

> 高コスト編成と低コスト編成で試合をして、18.4の非対称な2つの遊び方が実際に発生する

| 編成 | やっとるゲーム |
|---|---|
| 高コスト編成 | **「1体も落とさない」ゲーム** —— 交代と引き際の判断が命綱 |
| 低コスト編成 | **「1体だけ食う」ゲーム** —— 全部捨ててでも1回刺す |

**ここは機械では確かめられん。** 最後ににーくらが実際に戦わせて、
「守りのゲーム」と「攻めのゲーム」になっとるかを見る。
