# 整理：検査ゲートの棚卸し（2026-08-22）

## なぜやったか

**存在するのに誰も鳴らさん検査が、実害を出した。**

2026-08-21、Codex が作り直した技のデータを git へ入れるとき、8段の回帰チェーンが
緑なのを根拠にコミットした。しかし `tools/verify_cost.js` はそのチェーンに入っとらんかった。
結果、**にーくらの保存個体 BAZERGIUS が書き換えられとった事実**（装備技 1→3本、
覚えられる技 2→3本）を見逃し、掟「保存個体に指1本触れん」の違反をそのまま git へ入れた。

正しくは「緑やった」やのうて **「緑と言えるだけの検査を回しとらんかった」**。

数えたら、`tools/` の検査24本のうち **鳴っとったのは6本だけ**やった。

## どう選り分けたか

3つ測った。**合否だけで決めん**のが肝。

1. **今 緑か赤か** —— 赤のまま載せたらチェーン全体が止まる
2. **所要時間** —— 長すぎると誰も回さんくなって、それも別の形の空振り
3. **リポジトリを書き換えるか** ←★ これが決め手になった

### 載せられんかった（1本）

**`verify_store`** —— `data/` を実際に書き換える。「保存すると `data/` のファイルが
実際に変わるか」を確かめる検査やけん**設計どおり**やが、その巻き添えで
`data/monsters/BAZERGIUS.json`（**にーくらの保存個体**）と `data/creator-auto.json` が書き換わる。

**にーくらの保存個体を書き換える検査を、回帰チェーンへ黙って入れるわけにはいかん。**
単体でも赤（サーバー経由で開く前提が要る）。

> **未解決。にーくら判断が要る。** 直すなら「検査の後に元へ戻す」か
> 「使い捨ての個体を対象にする」。**このゲートが守っとる SAVE-01〜06 は今 誰も見張っとらん。**

### 設計上の除外（2本）

- **`verify_dev`** —— 作者自身が「`npm run verify` の4段には入れん。あれは `dist/` の
  正しさを見る連鎖で、`dist-dev/` は開発用の派生物やけん」と理由付きで書いとる。
- **`verify_migration`** —— `[backup.json]` を取る**一度きり**の移行検証（SAVE-07）。
  そのバックアップは `.gitignore` 済みでリポジトリに無い。役目を終えとる。

## 測り方で1つ学んだこと

**最初の計測で `verify_wire` は赤やった。** 直前に走った `verify_store` が `data/` を
汚した状態で走っとったけん。**1本ずつ木を戻してから測り直したら緑やった。**

1回の計測だけで「赤やけん載せん」と判断しとったら、**生きたゲートを1本捨てとった。**
検査を測るときも、検査の前提を揃えんと嘘の数字が出る。
