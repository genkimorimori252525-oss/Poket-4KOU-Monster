## 2. なんで「1か所」でやるか

弾速が既に同じ形をしとる（`battle.tpl.html:1625-1628`）：

```js
/* 弾速は技ではなく「撃った個体の素早さ」から決まる（計画15章） */
const spec = m.fx.travel
  ? {...m.fx, travel:{...m.fx.travel, speed:Math.round(m.fx.travel.speed*f.shotScale)}}
  : m.fx;
```

**撃つ直前に技データを個体で書き換える**形。ここに大きさも足す。

⚠ **これが特に効くようになった。** generator が6つやのうて**14個**に増えとる
（Codex が `hydro_pump` `flamethrower` `solar_beam` `roar_time` `electro_ball`
`psychokinesis` `close_combat` `big_butt_drop` を追加）。しかも今後の方針として
**技ごとに専用 generator を積み上げていく**（第7節）。

各クラスに書いたら**14か所、これから増え続ける**。`spec` を作る所でやれば**1か所**。

## 3. 実装

### 3-1. `Fighter` に getter を1本（`battle.tpl.html:429-434` の並びへ）

```js
get cdScale(){   return 1.55 - this.stats.spd/100*0.85; }        // 既存
get castScale(){ return 0.70 + (100-this.stats.spd)/100*0.60; }  // 既存
get shotScale(){ return 0.60 + this.stats.spd/100*0.90; }        // 既存
get powScale(){  return 0.80 + this.stats.atk/100*0.40; }        // ★足す
```

攻撃 0 → **0.80倍** ／ 50 → **1.00倍** ／ 100 → **1.20倍**。

既存3本と同じ `a + stat/100*b` の形。±20% は「この個体が持つと重い」が分かる程度で、
画面のレイアウトが壊れん幅。実戦で足りんかったら `0.40` を上げる。

### 3-2. `launch()` で `spec.sizeMul` を渡す

**大きさの倍率は1つのフィールドにまとめる。** 各 generator が自分の「大きさ」に掛ける。
`spec.size` を直接書き換えると、焼きコマと当たり判定で二重に効いたり効かんかったりして
追えんくなる（第4節）。

```js
const spec0 = m.fx.travel
  ? {...m.fx, travel:{...m.fx.travel, speed:Math.round(m.fx.travel.speed*f.shotScale)}}
  : m.fx;

/* 本演出の大きさは「撃った個体の攻撃」から決まる。
   近接は対象外 —— 打撃は触れて当てる技やけん、間合いが絵の意味そのもの。
   技データが scaleByPower:false と言うとったら従う（亜空切断がそれ）。 */
const scaled = (typeof MOVE_RANGE!=='undefined')
             && MOVE_RANGE.rangeOf(m) !== 'melee'
             && m.fx.scaleByPower !== false;
const spec = scaled ? {...spec0, sizeMul: f.powScale} : spec0;
```

### 3-3. 各 generator が `sizeMul` を読む

**これが新しい generator の契約になる**（第7節の方針で generator は増え続けるけん）：

> **新しい generator を作るときは、大きさの基準に必ず `sp.sizeMul`（既定 1）を掛けること。**

| generator | 大きさのキー | 焼く？ | 直す所 |
|---|---|---|---|
| `projectile` | `size` | **焼く** | `radius` / `draw` の `g.scale` / 尾の粒の大きさ の3か所 |
| `beam` | `width` | 焼かん | `draw` の `w` と、相殺の当たり判定 |
| `lightning` | `width` | 焼かん | `draw` |
| `aura` | `size` | 焼かん | `draw`（※遠隔。相殺に乗らん） |
| `shatter` | `size` | 焼かん | `draw`（※同上） |
| 新しい6つ（ranged/remote） | 各自 | 各自 | 同じ契約に従わせる |
| `slash` `close_combat` `big_butt_drop` | — | — | **近接やけん対象外。触らん** |

### 3-4. `projectile` だけ手当てが要る（焼きコマの罠）

焼いたコマは `BUILT` に**技ID**でキャッシュされとる（`moves.js:82-83`）＝**全個体で共有**。
だから `sp.size` を変えても**絵は変わらん**。3か所を別々に直す：

```js
class ProjectileFX extends BaseFX{
  get mul(){ return +this.sp.sizeMul || 1; }
  get radius(){ return Math.max(3,(this.sp.size||16)/2) * this.mul; }   // ← 相殺の判定
  ...
  // 尾の粒（update の中）
  Math.max(1, tr.size*this.sp.size*0.14*this.mul)
  ...
  draw(g){
    ...
    g.save(); g.translate(p.x,p.y);
    if(this.mul!==1) g.scale(this.mul,this.mul);        // ← 焼いたコマを拡大
    if(this.sp.shape==='shard'||this.sp.shape==='bolt') g.rotate(this.ang);
    ...
  }
}
```

⚠ `g.scale` は `rotate` の**前**に置く（後ろやと回転軸がずれる）。
⚠ `drawImpact()` は `BaseFX` にあって着弾の焼きコマを描く。**着弾は倍率をかけん**
（「敵へ向かっていく本演出」が対象。着弾は当たった後の絵やけん別）。
実戦で不自然やったら、そのとき `mul` の半分だけ掛ける等を試す。

### 3-5. `beam` は当たり判定の読み口を1つにする

今、相殺の判定が `sp.width` を**呼び出し側で**直に読んどる（`battle.tpl.html:1805`）：

```js
if(distToSeg(p.x,p.y,bm.f.x,bm.f.y,e.x,e.y) <= bl.radius+bm.sp.width*0.5+16){
```

倍率が入ると2か所（描画と判定）で食い違う危険がある。**アクセサを1本生やして両方そこを読む**：

```js
class BeamFX extends BaseFX{
  get mul(){ return +this.sp.sizeMul || 1; }
  get halfWidth(){ return this.sp.width*0.5*this.mul; }   // ★足す
```
```js
// battle.tpl.html:1805
if(distToSeg(p.x,p.y,bm.f.x,bm.f.y,e.x,e.y) <= bl.radius + bm.halfWidth + 16){
```

`draw()` の中の `const w=Math.max(1,Math.round(s.width*(li+1)/P.length));` にも `*this.mul`。

## 4. 亜空切断を外す

⚠ **`data/moves/library.json` の亜空切断は `generator:"shatter"` ＝遠隔**。
（`src/moves.js` の内蔵 `MOVES.akuu` は `slash`／`melee` で別物。にーくらが触るんは library の方）

つまり**放っといたら変化してしまう**。明示的に切る：

```jsonc
"亜空切断": { "fx": { "generator":"shatter", ..., "scaleByPower": false } }
```

`scaleByPower !== false` で判定しとるけん、**書いてない技は全部 true 扱い**（既定で連動する）。
亜空切断だけ `false` を書く。

> 既定を true にした理由：にーくらが挙げた例外は亜空切断1本だけやったけん。
> 逆にすると新しく作る技すべてでチェックを入れる手間が要る。

**影響を受ける既存技**：`灼熱弾`（projectile＝遠距離）。これは連動してよい。

## 5. チェックボックス（技制作ツール）

`fx.scaleByPower` を技ラボと制作ツールの両方から切り替えられるようにする。
**`src/movelab.js` は両方から使われとる**けん、そこに1本置けば2画面ぶん済む。

- ラベル：**「強さで大きさが変わる」**
- 既定：ON（＝`scaleByPower` を書かん＝true）
- OFF にしたら `fx.scaleByPower = false` を書き込む
- **近接の generator を選んどるときは出さんか、灰色にして「近接は対象外」と出す**
  （出しっぱなしやと「入れたのに効かん」になる）
- 置き場所：`mlScreen`（画面演出）の隣あたり。generator 固有やのうて技全体にかかる設定やけん、
  `SCHEMA`（generator ごとのスライダ表）には**入れん**

## 6. 検証

`tools/verify_power_scale.js` を作る（`tools/verify_look.js` が手本。
Playwright／スクショ／NGなら終了コード1／`PW_CHROMIUM` 対応）。**目視やのうて数える**：

1. 攻撃30・50・100 の個体が同じ遠距離技を撃ったとき、**描画ピクセル数が単調に増える**
2. 近接技は攻撃を変えても**ピクセル数が完全一致**する（対象外の証明）
3. `scaleByPower:false` の技は攻撃を変えても**完全一致**する（亜空切断の証明）
4. `ProjectileFX.radius` と実際に描かれた絵の幅の比が、攻撃を変えても**一定**
   （＝絵と当たり判定がズレとらん証明。第3-4節の罠の再発防止）
5. **決定論チェックが通る**（`battle.tpl.html` の「決定論チェック」ボタン／`determinismTest()`）
   —— `powScale` はステータスから決まる純関数やけん壊れんはずやが、必ず確かめる

> 技を作る際は既存の素材をつかわずに、それぞれに専用 generator・専用描画クラスを新設する

>    絵が要るなら `fx_core.js` のジェネレータ（projectile / beam / slash / lightning / aura / shatter）を

### やること
